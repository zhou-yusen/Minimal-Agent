# Phase 1 任务——需求与架构

## 解决的问题

在开始实现之前，把宽泛的笔试要求拆成一组明确的职责和稳定契约。

## 实现/设计工作

- 盘点功能需求、失败场景、状态、上下文、Trace 和测试义务。
- 明确 Agent 循环的唯一负责人（`AgentRuntime`）。
- 只定义确定性测试或必要持久化所需的可替换边界。
- 冻结 Session 身份、循环步语义、保存点、上下文压缩行为和推理数据策略。
- 将 Phase 2–9 映射为范围明确的交付物。

## 关键取舍

- 采用 SQLite JSON Session 文档，而非规范化或事件溯源存储。
- 工具顺序执行，而非并行执行。
- 完整持久化可见历史，但限制推理上下文。
- 使用 Provider-neutral 领域对象，并只提供一个官方 SDK Adapter。
- 核心 Runtime 工作后再增加薄 HTTP/CLI Adapter。

## 验收条件

- `AGENTS.md` 说明约束和工作规则。
- `docs/architecture.md` 包含要求的八个部分和明确标记的冻结版本。
- 后续每个阶段都有范围明确的任务文档，包含实现细节、验证方式和验收条件。
- 设计覆盖所有要求的异常和测试场景。
- 本阶段不创建 Runtime 源代码或依赖文件。
